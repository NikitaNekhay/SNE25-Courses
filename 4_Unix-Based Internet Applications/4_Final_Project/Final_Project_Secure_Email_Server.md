**Abstract:**

This project presents the design, deployment, and validation of a secure email server infrastructure based on Postfix and Dovecot on a Linux virtual private server.

The system was implemented using Postfix as the Mail Transfer Agent (MTA) and Dovecot as the IMAP server, with virtual mailboxes for domain users. Transport Layer Security (TLS) was enabled using Let’s Encrypt certificates to protect SMTP and IMAP communications. Email authentication mechanisms including SPF, DKIM, and DMARC were configured to ensure message authenticity and improve deliverability. SpamAssassin was integrated into the mail flow to detect and filter unsolicited messages using rule-based and Bayesian analysis. User access and mail flow were tested using the Thunderbird email client.

The deployed server successfully handled authenticated mail submission, encrypted mail retrieval, internal and external email delivery, and spam classification. Verification against external providers (Gmail) confirmed correct SPF, DKIM, and DMARC alignment. The results demonstrate that a fully functional and secure email system can be implemented using open-source components when configuration, DNS alignment, and authentication are correctly applied.

**Stack:**

- Postfix — Mail Transfer Agent (send/receive mail)
- Dovecot — IMAP server
- SSL/TLS (Let’s Encrypt)
- SpamAssassin — Filter spam before it reaches user mailboxes
- SASL — Authenticate users securely for sending/receiving mail
- Thunderbird — GUI

### Step 2.2: Configure Postfix Main Configuration

- Made backup for [main.cf](http://main.cf) file so that I can copy params

![image.png](screenshots/image_5.png)

Figure.

- Edited the main Postfix configuration file:

```bash
sudo nano /etc/postfix/main.cf
```

- Added the following parameters:
    - **Identity configuration**
        - `myhostname` and `mydomain` were explicitly defined to:
            - ensure consistent SMTP banner presentation,
            - avoid mismatches during HELO/EHLO negotiation.
    - **Destination handling**
        - `mydestination` was limited to localhost only to:
            - prevent Postfix from treating the main domain as a system-user domain,
            - correctly route domain mail to virtual mailboxes.
    - **Virtual mailbox design**
        - Virtual users were implemented to:
            - avoid creating Linux system users for mail accounts,
            - simplify mailbox management,
            - improve security isolation.

```bash
# Basic Settings
myhostname = mail.nekhaynikita.ru
mydomain = nekhaynikita.ru
myorigin = $mydomain
mydestination = localhost

# Network Settings
inet_interfaces = all
inet_protocols = ipv4

# Mail Storage
home_mailbox = Maildir/
mailbox_size_limit = 0
recipient_delimiter = +

# Virtual Mailbox Settings (for virtual users)
virtual_mailbox_domains = nekhaynikita.ru
virtual_mailbox_base = /var/mail/vhosts
virtual_mailbox_maps = hash:/etc/postfix/vmailbox
virtual_minimum_uid = 100
virtual_uid_maps = static:5000
virtual_gid_maps = static:5000

# SMTP Client Restrictions
smtpd_relay_restrictions = permit_mynetworks,
    permit_sasl_authenticated,
    defer_unauth_destination
```

### Step 2.3: Configure SMTP Authentication

## Step 7: SpamAssassin for blocking spam

![image.png](screenshots/image_47.png)

- Configuration
    - `nano /etc/spamassassin/local.cf`
        - *Bayes Classification* is a Supervised machine learning approach for classification. A Bayesian Classifier is **a  system based on Bayes' decision theory, where probabilistic models of features are used to predict the class label of a new sample**. It predicts the class label by utilizing Bayes' rule when the class is unknown.

## Summary

This project demonstrated the end-to-end deployment of a secure, production-style email server using open-source technologies on a Linux VPS. The system integrated Postfix for SMTP mail transport, Dovecot for IMAP access, virtual mailboxes for domain users, and TLS encryption to protect data in transit. Email authentication mechanisms (SPF, DKIM, and DMARC) were implemented and validated to meet modern email security requirements and ensure compatibility with major email providers.

A significant part of the work involved troubleshooting real-world configuration issues, including DNS misalignment, virtual domain handling errors, DKIM key mismatches, and SpamAssassin integration loops. These issues highlighted the tight coupling between mail server configuration, DNS records, and authentication policies. Resolving them required systematic log analysis, protocol-level testing using OpenSSL and Telnet, and iterative configuration refinement.

The final system successfully delivered encrypted, authenticated, and spam-filtered email between local users and external providers such as Gmail. This confirms that a secure and reliable email infrastructure can be built using Postfix and Dovecot when industry best practices are followed. The project provided practical experience with mail protocols, security mechanisms, and operational troubleshooting that closely reflects real-world system administration tasks.
